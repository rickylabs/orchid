# Lesson — 2026-10-28

An acknowledged state update is weaker than proof of the intended work. A native goal can read active without a new turn, and a temporary app-server process cannot certify that the live TUI continued. Bind recovery to the shared daemon, reserve effects durably, and require native progress within one deadline that observations cannot renew.

Admission authorization and checkout authority also need separate names. An immutable authorization revision may be old by design; a new run must still fetch the current default head unless its bound brief explicitly chooses another base. Record the actual commit before any agent seat exists.

Gate notes: fake launch transports must return verified preparation outputs, and short fixture deadlines can expire before the first read under concurrent mutation compilation. Keep mutation source copies isolated, retain failures, and re-run the final configured suite on an unchanged source snapshot.


Round 2: an exhausted recovery state must keep observing external native authority. Retirement guards and continuation ownership are different responsibilities: an open PR should block teardown while allowing a manual goal resume to restore PR supervision. Native active status alone is insufficient after an unproven automatic start; retain the observed timestamp/status and the failed-turn notice key. Regression tests must compile against the defect baseline without adapting private production fields, and mutation anchors need uniqueness checks before expensive compilation.
