# Live native binding: measured gap

At Orchid `origin/main` 48a1937, registration obtains the official ID from `agent_started`, then makes one exact `agent get` read if absent (`cmd/divybot/main.go:598-628`). It writes the private `NativeSessionID` only if one of those reads succeeds (`main.go:625-630`). After prompt delivery, goal setup polls that same exact occupant at most 40 times, 250 ms apart, and writes the binding if it succeeds (`cmd/divybot/native_goal.go:100-142`, `main.go:2780-2786`). Supervision revisits the live job every tick but has no binding retry (`main.go:2191-2199,2792-2865`). Thus the current code can bind during launch; it is not designed to wait until run end. The gap is a native hook report that arrives after the roughly 10-second goal setup window.

Private receipt timing, reduced to issue number and UTC time (no native IDs or paths): #392 dispatch was written 2026-09-27 23:21:08.545 and its binding updated 23:21:31.020, about 22.5 seconds later; the final binding has a native ID. #393's initial binding was written 23:43:39.745 and dispatch was written 23:43:48.443. Its binding still lacked a native ID during 50 five-second feed samples and after the agent's 23:46:29 completion comment. The #393 feed consequently reported `ancestry_unavailable` throughout. These observations show missed live binding, not proof of the precise hook arrival time.

Plan: on each live supervision tick, if a Codex job has a private dispatch receipt and no native ID, validate its persisted receipt and original pane/workspace, make one exact `herdr agent get`, accept only the official source-tagged ID for that occupant, and atomically write the private 0600 binding. Do not retry native goal creation, repurpose public ancestry, or infer an ID from a pane. A persisted receipt key allows retry after a divybot restart. Test absent→available, wrong occupant, invalid/uncertain receipt, and private publication; kill the supervisor wiring mutation before PR.
