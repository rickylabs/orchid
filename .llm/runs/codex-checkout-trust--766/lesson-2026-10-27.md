# Lesson — 2026-10-27

Prove the trust lookup at the layer that reads it. A remote TUI can ignore process and thread trust while consulting daemon user configuration. Use the native config API and pair the exact checkout entry with its cleanup.

A successful control must exercise the failing behavior: a projectless folder was ineffective, while the same disposable Git checkout with a project config layer went red → green → red as its daemon trust entry was written and removed. Native readiness plus a native resume record establish success without screen access. Native log persistence can lag readiness.

Quoted config API key segments and CLI TOML overrides have different parsers. For the 0.164 config API, escape backslash and quote in the path segment while retaining Unicode; null removes the exact entry. See `codex_checkout_trust.go:21` and the installed protocol/source citations in plan.md.

An evaluator process that exits without reviewing is no certification. Record a provider credential refusal as unproven and disclose it in the PR; never turn local test success into an independent PASS.

## Round 3 lessons

A filtered issue map is an adoption view, not the complete liveness set. Capture every raw fleet cwd before filtering and persist it on adoption. A physical daemon may have several host aliases, so protect paths globally rather than using the observer name as ownership.

An event-driven tick can fire much faster than a recovery interval. Pace failed attempts as well as successful ones, and use explicit lifecycle failures to request immediate recovery. A default configuration pointer proves neither Codex placement eligibility nor an enabled launch switch.

Mutation tests need independent assertions for distinct guards. Immediate bounded-release revocation can mask a missing released-job guard in the subsequent orphan sweep; test those behaviors separately. Older repository mutation scripts mutate their source tree, so execute them in isolated copies alongside the normal/race suites.
