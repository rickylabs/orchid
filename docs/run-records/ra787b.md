# Native-run shared socket: implementation evidence

The native-run read endpoint uses its existing configured pathname, binds a mode-0660 socket in an operator-provisioned 0700 or setgid 2750 parent, preserves the inherited group, and checks each reader's kernel UID. An explicit `ORCHID_NATIVE_RUN_PEER_UID` selects the observer UID; the default remains the daemon UID. Missing parents and invalid peer configuration refuse only this endpoint with fixed named reasons; supervision continues. Refs [harness#787](https://github.com/rickylabs/harness/issues/787).

## Design and proof

An independent cross-family plan review approved this scope after explicitly incorporating the owner-grant permission mutation anchor and the configured-UID test in the existing isolated root CI lane. The existing owner-grant endpoint keeps mode 0600. Native lookup/subscription schemas and framing are unchanged.

The regression was run before implementation and failed by assertion: `socket mode = 0600, want 0660` (exit 1). With the implementation restored, the focused native-run suite passed (exit 0). A separate compiled mode mutant changes the native socket's mode to the default-like 0755: compilation passes (exit 0), and `TestNativeRunConfiguredSocketMode0660` fails by assertion `socket mode = 0755, want 0660` (exit 1). Exact restoration passes (exit 0).

The tests also exercise missing-parent refusal through a real once-mode supervision tick, replacement of stale 0600 and 0660 endpoints, inherited group, shared parent preservation, cleanup, malformed peer configuration and rejection of an unconfigured kernel UID. The isolated root CI lane additionally proves a different configured UID can subscribe and look up through actual setgid parent and socket permissions, while another UID with pathname access is refused. That privileged proof is unproven in an unprivileged local run.

## Deployment boundary

No live daemon, container mount or observer configuration was changed. Cockpit's current client still hard-requires its own UID and a 0700/0600 endpoint; it needs an explicit shared-server access policy before using this listener. The existing wire protocol remains exact. Observer enrichment certification, Home count parity and completion removal require consumer adoption plus operator deployment, and are not claimed by this server PR.

These tests compared an old device/inode snapshot after the closed stale inode had been unlinked
and could already be recycled. The fixture now holds a no-follow Linux O_PATH reference until
test cleanup; this pins filesystem identity without keeping a socket listener alive. All existing
replacement, exact0660, lookup, parent-preservation and cleanup assertions remain intact.
Production socket behavior is unchanged. Refs [Harness #790](https://github.com/rickylabs/harness/issues/790).
