# Matrix resolution before every spawn

New dispatches resolve NetScript's pinned matrix before choosing an account and host. The
dispatcher writes a private receipt before its single launch effect. Resolution, authorization,
quota, profile or persistence failures refuse the attempt. Existing jobs can still be adopted
and supervised; adoption does not manufacture a new matrix receipt.

Start with `cmd/divybot/matrix.go` and its tests. `matrix-bridge.ts` imports the existing
NetScript routing policy and runs its existing JSON CLI in place. There is no copied fleet
matrix, provider adapter, NetScript source extraction or Harness build dependency.

## Configuration and brief

The operator's private `matrix` configuration supplies:

| Key | Contract |
| --- | --- |
| `source`, `revision` | Clean NetScript checkout and exact expected source commit. Both required; checked before and after resolution. |
| `receipt_root` | Existing directory with mode 0700, outside any Git checkout, with no symlink aliases. Required. |
| `target_revisions` | Target repository to exact profile/source commit mapping. Required for each target. The launched worktree uses that commit. |
| `pins` | Optional map of arbitrary names to `{model, effort}` values. No implicit entries. Replace values in private configuration without changing dispatcher source. |
| `grants` | Immutable authorizations bound to an issue's global node ID, target repository and digest of the complete title/body. |

Do not commit operator configuration, receipt contents or actual execution identifiers. A grant
is launch configuration, not a second decision ledger. Its `brief_digest` is SHA-256 of Go's
JSON encoding of `{Title, Body}` in that order; it includes the complete body, not the parser's
possibly shortened prompt. Fields `issue_id`, `repo`, `tier`, `role`, `authorization` and
`ownerMatrixOverride` are defined by `MatrixGrant`. Duplicate grants for the same brief refuse.
Editing a title/body cannot reuse its authorization. An old grant stays immutable.

A brief uses the existing `/swarm` grammar with `tier`, `role`, `profile`, and optional `pin`.
Direct `model` and `effort` requests remain possible. A named pin cannot also carry direct
model/effort values. Duplicate routing keys refuse. Keep dispatched briefs free of fenced code.
The default profile is the shipped `leaf.md`; its Markdown routing row supplies the role.
Missing profile files, unsupported row syntax, conflicting roles and missing workload tiers
refuse. The coordinator profile uses its own declared scope and the coordinator matrix.

## Authority and configurable pins

The normal route is always resolved first. A matching pin adds no authority. A pin that skips
that selected route requires a trusted `ownerMatrixOverride` grant, including its logical
model, effort, owner authorizer, rationale and repository-relative worklog path. For a named
pin, that same trusted override also carries `pin` equal to the requested configuration key;
a different or missing name refuses a deviation. Changing the configured value cannot reuse
a grant for a different model/effort. The exact
entry generated by NetScript's `ownerMatrixOverrideWorklogEntry` must exist at the pinned
target revision. Issue prose cannot supply this authority. Privileged-tier authorization is
validated separately, including the runtime authorizer union; an override never waives it.
Profile transport restrictions remain active even on the upstream override path.

NetScript's [first-party guide](https://github.com/rickylabs/netscript/blob/f3324909e0896cedc9729005bac5f508e122d6c6/.llm/tools/agentic/README.md#L408)
documents the owner grant. No default configurable pin set was found in that source's matrix
CLI. The owner's separate requirement makes Orchid's pin values configurable; it does not
justify inventing NetScript defaults. Harness PR #348 separately derives its pinned-model
identities from replaceable project configuration.

## Admission and observation limits

Only the existing native Claude, Codex and Agy mechanics are advertised. Codex's existing
noninteractive variant can use the same selected native model. Router substitutions and
unsupported transports refuse. Admission requires fresh, nonexpired readings for both
subscription windows plus governor capacity. Unknown entitlement is unavailable; selecting a
sibling model cannot refill an exhausted subscription. Agy currently has no qualifying meter
in this dispatcher, so this change does not claim Agy admission works.

All evaluator roles refuse until a real observed model/session contract is available. No native
observer is added. The owner approved this boundary. The bridge returns a closed refusal record
with `status: inconclusive` and `reasonCode: observer-unavailable`; the common attempt records
that same sanitized diagnostic and cannot reach host selection, launch persistence or spawn.
The reason reuses the I1 receipt's existing unknown-observation vocabulary. It does not imply
that an evaluator ran or that an independent gate passed. Pane and workspace handles are not
model session identities.

Receipts follow Harness PR #342 schema version 1. All observations remain explicitly unknown
because this adapter has no independent runtime observer. The requested effort records the
matrix request, while the private binding retains its resolved concrete effort. Such receipts
are structurally valid and return `unproven`, never an invented pass.

The receipt and its private binding are synced before a single-use, command-bound handle can
reach `Host.spawnAgent`. A durable reservation fences the same issue/repository/brief across
restarts. Any failed or ambiguous launch remains fenced; an operator must reconcile actual
effects before explicitly authorizing a distinct attempt. Automatic retry cannot erase that
record. No native observation is asserted, so a dispatch acknowledgement cannot turn the
matrix receipt green. Existing job persistence is not a substitute for the receipt fence.

## Gates and rollout

`go test -race ./...`, `go vet ./...`, and `go build ./cmd/divybot` are actual CI stages.
Tests require Deno and exercise the bridge against a committed synthetic first-party fixture,
including replacement model identities, pins, authority, profiles, malformed output, process
failure, timeout and dirty source. Process cancellation kills the subprocess group on the
Unix dispatcher platforms. Tests invoke the actual common attempt and the actual bare effect
boundary. Public fixtures are synthetic.

The optional `MATRIX_PROBE_SOURCE` / `MATRIX_PROBE_REVISION` local gate runs the same bridge
against a clean, real checkout without spawning. CI does not possess or need a fleet checkout.
Local read-only resolution is not live acceptance. This source PR neither configures nor
deploys the daemon. Independent source review, supervisor sign-off and separately authorized
live coverage checks remain required before claiming the deployed fleet satisfies I1–I3.

## Per-issue dispatch read

The existing private reservation also holds `record/dispatch.json`. It records schema version,
coordinator run identity, the **inbox** repository and issue number, selected profile/provider/model/effort,
native CLI source and a null parent for an inbox root dispatch. Target repository and inbox issue
numbers must never be paired. The exact pane and workspace returned by workspace creation are
synced before the execution effect. States are `reserved`, `launching`, `dispatched`, or `uncertain`;
acknowledged dispatch does not claim the agent is currently running. An ambiguous launch stays
reserved against automatic replay and retains its exact location.

Harness's existing `dsh-telemetry runs --json` reads these records when its private
`DSH_TELEMETRY_DISPATCH_ROOT` configuration names the same receipt root. It emits additive
`dispatches` rows with issue, parentRunId, location and dispatchState alongside canonical route
evidence. The directory and native handles remain operational data, never publication artifacts.
No extra collector or daemon is introduced.

This binds requested provider/model/effort and issue/pane context. Provider is preserved from
NetScript ResolvedDelegationRoute, not inferred by Orchid. Native session identity and observed
route are still unavailable from this launch interface. Transport
and model family are not substitutes for router evidence. No transcript is matched by cwd.
Per-run spend/tokens remain unavailable until an explicit native-session association exists;
provider-wide headroom remains separately scoped governance evidence. Installation and the
first live issue dispatch remain unevidenced; this draft does not claim alpha acceptance.

## Refusal diagnostics

Every refused common dispatch attempt reports a closed reason code, fixed field name and
remediation in the operator log and an inbox comment. `matrix_diagnostics.go` is the vocabulary;
private values and subprocess errors are never copied into either surface. For example, absent
source configuration reports `reason=source-missing field=matrix.source`. Authorization,
profile, quota, host placement and receipt persistence have separate reasons. Evaluator
refusal remains `inconclusive` / `observer-unavailable`.

Successful comments are deduplicated by issue identity, complete brief digest and reason in
private dispatcher state. Failed comments retry on a subsequent poll. A crash after posting
but before saving can duplicate a comment; it cannot authorize a launch. A corrected
configuration can be reconsidered normally; a diagnostic is not a launch reservation.
Dry runs log the explanation but do not post comments or persist notification state.
