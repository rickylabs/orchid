# Verified native alerts

Native blocks and post-launch Orchid policy alerts use Herdr's `notification.show`
CLI wrapper. Each producer reopens the private dispatched receipt and verifies the
selected server scope, unique terminal occupant and native conversation identity.
Claude and Codex blocks also require their verified vendor hook receipt; detected
screen status alone cannot produce an alert.

Messages contain fixed vocabulary and no native identifiers, paths, titles or
usage data. A three-second deadline bounds each attempt. Two persisted keys per
job deduplicate native block episodes and policy alerts, including after restart.
The reservation precedes best-effort delivery, so an uncertain notification is
not replayed. Herdr's notification preferences and rate limits remain authoritative.
Existing mobile push and external delivery continue independently.

An admission refusal without a dispatched binding has no verified native
recipient and remains on the existing issue and external delivery interfaces.
No default workspace or guessed occupant receives that alert.
